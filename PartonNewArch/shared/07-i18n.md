# 07 — Internationalization (i18n)

**Status:** `accepted`  
**Last updated:** 2026-10-09  
**ADR:** [0023 — i18n Turkish-primary](../backend/adr/0023-i18n-turkish-primary.md)  
**Architecture:** [`../04-application-architecture.md`](../04-application-architecture.md) §15.6  
**Related:** [Push UX](05-push-notifications-ux.md) · [A11y](06-accessibility-wcag.md) · [API conventions](../backend/06-api-conventions.md) · [Privacy](../backend/17-privacy-kvkk-gdpr.md)

> PartOn launches **Turkey-first**. Product UI, push copy, SMS templates, API user-facing errors, and legal notices ship in **Turkish** as the primary language. English is a **secondary** locale prepared in the same key structure—not a parallel product rewrite.

---

## Verdict

| Topic | PartOn stance |
| --- | --- |
| Primary locale | **`tr-TR`** (Turkish — Turkey) |
| Default when unset | **`tr-TR`** |
| Secondary locale (v1+) | **`en`** (generic English) — complete keys over time; not required day-1 for every string |
| Source of copy | Locale resource files / catalogs — **no** user-facing hardcoding in components |
| Shared keys | Same message **ids** across mobile, admin, Nest (push, errors) where text is shared |
| Formatting | `tr-TR` dates, numbers, **TRY** currency; timezone default **`Europe/Istanbul`** |
| HTML / a11y | `lang="tr"` (or active locale) |
| RTL / other languages | **Hold** for v1 (no Arabic RTL product track yet) |
| Case catalog | Turkish acceptance source: `parton_case_tests_tr.json` |

---

## 1. Locale resolution order

```text
1. Explicit user profile locale (if set)
2. Active client preference (app/OS setting synced on login)
3. Accept-Language (web) / device locale (mobile) if supported
4. Fallback: tr-TR
```

| Client | Store |
| --- | --- |
| Mobile | Secure prefs + `PATCH /api/v1/users/me` (`locale`) |
| Admin web | User setting + `localStorage` mirror; `lang` on `<html>` |
| Nest outbound | Recipient’s `locale` for push/SMS/email; else `tr-TR` |

Unsupported device locales → **`tr-TR`** (do not show mixed half-translated UI).

---

## 2. Resource organization

```text
packages/i18n/                 # or apps/*/src/locales until package lands
  tr-TR/
    common.json
    auth.json
    jobs.json
    shifts.json
    tokens.json
    notifications.json       # push + inbox strings (align ADR-0021)
    errors.json              # maps error.code → user message
  en/
    … same files / keys …
```

| Rule | Detail |
| --- | --- |
| Key style | Dot or nested JSON: `jobs.apply.confirmCta` |
| Interpolation | ICU / i18next style: `{{jobTitle}}`, plurals for TR |
| Ownership | Product/copy owns TR; eng owns keys; no TR-only forks in code |
| Forbidden | Concatenating sentences in code; embedding copy in NativeWind `className` |

**Libraries (proposed Adopt):**

| Surface | Library |
| --- | --- |
| Mobile + Admin | **i18next** + **react-i18next** |
| Nest | Same JSON catalogs via shared package, or **nestjs-i18n** reading the same files |
| Formatting | `Intl` (DateTimeFormat, NumberFormat) with `tr-TR` / `en` |

## 3. What must be localized

| Surface | Turkish-primary |
| --- | --- |
| Mobile UI | All screens, empty/error states, permissions explainers |
| Admin UI | Shell, queues, forms, toasts |
| Push / inbox | Template title/body/inboxBody — [05](05-push-notifications-ux.md) |
| SMS OTP | Provider templates in TR |
| API `error.message` | User-safe Turkish (stable `error.code` stays English enum) |
| Legal / policies | TR versions authoritative for KVKK; EN when offered |
| Email (if any) | TR-first |

| Keep language-neutral | Examples |
| --- | --- |
| `error.code` | `INSUFFICIENT_TOKENS` |
| Deep-link `type` | `shift.confirm_3h` |
| Logs / metrics | English keys OK |
| Admin internal codes | Enums |

## 4. Formatting & regional defaults

| Concern | `tr-TR` default |
| --- | --- |
| Locale tag | `tr-TR` |
| Timezone | `Europe/Istanbul` (display); store UTC in DB |
| Currency | **TRY** — `Intl.NumberFormat('tr-TR', { style: 'currency', currency: 'TRY' })` |
| Dates | Prefer absolute local: `14 Eki 2026 09:00` style via Intl |
| Relative | “3 saat içinde” via i18n keys + duration |
| Phone | E.164; display national TR format in UI |
| Sort / search | Turkish locale-aware where lists are client-sorted |

Server never assumes client TZ for shift windows — job/branch TZ rules in domain; UI formats for user.

## 5. Nest API conventions

| Item | Practice |
| --- | --- |
| `error.code` | Stable English SCREAMING_SNAKE |
| `error.message` | Localized for `Accept-Language` / user locale (TR default) |
| `error.details` | Machine fields; not prose |
| OpenAPI examples | Prefer TR user messages in examples for Turkey launch |
| Push templates | Resolve locale server-side before FCM send |

```http
Accept-Language: tr-TR, tr;q=0.9, en;q=0.8
```

## 6. Mobile & web implementation notes

### Mobile

- Wrap app in i18n provider; default `tr-TR`
- Settings: language picker when `en` ships; until then TR-only OK
- Dynamic Type + TR copy must not clip (a11y)
- Deep links unchanged (locale-neutral `type`)

### Admin web

- `<html lang="tr">` or active locale
- shadcn labels via `t('…')`
- Date pickers / tables use `tr-TR` locale adapters

### Pseudo-locale / QA

- CI optional: missing-key lint (fail if `en` key missing when EN enabled; always fail missing `tr-TR`)
- Review TR copy for marketplace tone (CASE-UX)

| --- | --- |
| Multi-country copy (DE, AR, …) | Hold until market ADR |

## 8. Delivery

## Checklist (PR)

- [ ] No new user-facing literal strings in components (use keys)  
- [ ] `tr-TR` value present for every new key  
- [ ] Push/SMS/email use recipient locale → TR default  
- [ ] `error.code` English; `error.message` localized  
- [ ] Dates/money via `Intl` + `tr-TR` / TRY  
- [ ] `lang` attribute matches active locale (web)
