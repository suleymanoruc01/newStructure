# 05 — PM2 (Nest web process manager)

**Status:** `accepted`  
**Last updated:** 2026-10-10  
**ADR:** [0031 — PM2 for Nest web](../backend/adr/0031-pm2-web-process-manager.md)  
**Deployable:** Nest modular monolith (REST + admin static) — ADR-0001 · ADR-0014  
**Ops:** [`../07-environments-and-ops.md`](../07-environments-and-ops.md)

> **PM2** manages the PartOn **web** process: Nest serving `/api/v1` and the Vite admin SPA. Not used for mobile. Local watch-mode stays Nest CLI; PM2 is staging/production (and optional local parity).

---

## Verdict

| Topic | Stance |
| --- | --- |
| Process manager | **PM2** (Adopt) |
| What it runs | `apps/backend` built Nest app (API + `/admin` static) |
| Config | `ecosystem.config.cjs` in repo (no secrets) |
| Local dev | `nest start --watch` / turbo — PM2 optional |
| Staging / prod | `pm2 start|reload` from deploy pipeline |
| Multi-instance | Default **`instances: 1`** until SSE affinity designed ([19-sse](../backend/19-sse.md)) |
| Banned as primary | forever, nodemon-in-prod, unmanaged bare `node` as the release path |

---

## 1. Layout

```text
apps/backend/
  dist/                    # build output
  ecosystem.config.cjs     # or repo-root ecosystem — pick one in scaffold
```

Example shape (agents fill paths/versions at scaffold — do not invent prod secrets):

```js
module.exports = {
  apps: [
    {
      name: 'parton-api',
      script: 'dist/main.js',
      cwd: './apps/backend',
      instances: 1,
      exec_mode: 'fork',
      env_file: '.env', // or inject via host secrets — never commit .env
      max_memory_restart: '512M',
    },
    // Stage C optional:
    // { name: 'parton-worker', script: 'dist/worker.js', instances: 1, ... }
  ],
};
```

Use **latest stable** `pm2` (`npm i -g pm2` or project dependency — verify with registry; do not invent pins).

---

## 2. Commands (ops)

| Action | Command |
| --- | --- |
| Start | `pm2 start ecosystem.config.cjs --env production` |
| Zero-downtime reload | `pm2 reload parton-api` |
| Status / logs | `pm2 status` · `pm2 logs parton-api` |
| Boot persistence | `pm2 save` + `pm2 startup` on the host |

Deploy pipeline: build admin → build Nest → migrate → `pm2 reload`.

---

## 3. Health & reverse proxy

| Layer | Role |
| --- | --- |
| PM2 | Keep Nest process alive; restart on crash |
| Nest | `/health/live` · `/health/ready` |
| **NGINX** | TLS terminate → Nest — [06-nginx.md](06-nginx.md) · ADR-0032 |
| Cloud LB (AO-10) | May sit in front of NGINX; VM hosts still use NGINX |

Do **not** bind PM2 success to FCM/SMS readiness (degraded mode OK — [07-ops](../07-environments-and-ops.md)).

---

## 4. SSE / cluster caution

Foreground realtime uses **SSE** (ADR-0012). Until sticky sessions or a shared pub/sub fanout exists:

- Keep **`instances: 1`** (fork) for the API app  
- Do not enable `cluster` mode just because “web scale”  

Revisit with an ADR when horizontal Nest is required.

---

## 5. Agent rules

1. Scaffold `ecosystem.config.cjs` in S0/S9 ops slice — no secrets in git.  
2. Do not introduce a separate Next.js/PM2 admin process.  
3. Do not replace PM2 with forever/nodemon for staging/prod docs.  
4. Ask once for host SSH/deploy secrets when wiring real staging — never stub fake `pm2` success.  
5. Cloud vendor (AO-10) open: still document PM2; if containers win later, keep ecosystem as reference or run Nest as PID 1 — do not delete the ADR without supersede.

---

## 6. DoD

- [ ] `ecosystem.config.cjs` present and documented  
- [ ] Staging deploy uses `pm2 reload` (or start) for Nest  
- [ ] Admin static served by same Nest process under PM2  
- [ ] `instances: 1` until SSE scale story lands  
- [ ] No secrets in ecosystem file
